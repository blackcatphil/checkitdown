# Working agreement — how to work with me on CHECK IT DOWN

## Always end with a brief
After **every** build that completes, and **whenever a decision is needed**, produce a brief I can paste straight back to Claude. Do not just summarise in chat.

- Keep it in `Check It Down - design brief.md` — update that file rather than creating new ones, so there is one current source of truth.
- Open it with **How to verify**: the measured invariants (numbers, not adjectives) a verifier must re-check, and an instruction to probe rather than eyeball.
- Keep the whole brief current in the same pass: file map, screen checklists, data rules, tweak defaults, and known limitations. A brief that contradicts the build is worse than no brief.
- End with **decisions needed** — numbered, specific, each with the options and my default if I say "decide for me". If nothing is blocked, say so explicitly.
- Show me the file (open it) as part of finishing.

## Standing rules for this product
- The product is **CHECK IT DOWN** (checkitdown.com). "Poker Map Alpha" is a retired placeholder name.
- **Desktop first**, mobile deferred but coming — never design an interaction with no touch equivalent.
- Every number carries provenance: verified with a date, or tilde'd and marked unverified. Nothing is stated as fact without a real source behind it.
- Placeholder content must be declared as placeholder in the brief.
- Verify roster/count claims against live sources and record the reconciliation, not just the number.
- **No gold, no bronze, anywhere** — it is what makes a brand read as a casino, and we are the independent tool that audits them.
